### How correctness is checked

`tests/reference.py` is a second, deliberately plain implementation of the rules in the README. It reads the catalogue JSON directly (no RDF, no SPARQL) and checks every film one by one. The tests compare the real recommender against it:

| Test file | What it proves |
| --- | --- |
| `test_recommendations.py` | Five worked example groups (shared tastes, conflicting tastes, balanced beats one-sided, no common movie, liked film) return the hand-computed shortlist and scores, directly and through the API. 90 seeded random groups of 2, 4 and 8 people return the same films, scores and per-member percentages as the reference. Every pick matches at least one like of every member; no pick hits any member's dislike (checked on full candidate lists, not only the top 5); each dislike kind (genre, subgenre parent, person, single film) removes what it should. Explanations name exactly the likes that connect, and the group score is 60% weakest + 40% average. |
| `test_explanations.py` | Each like now carries a reason (`this film`, `via Psychological Thriller`, `directs it`, `same director: Christopher Nolan; shared genre: Thriller`, ...). Exact sentences for known cases, and on 60 random groups every reason is checked against the catalogue facts. |
| `test_genres.py` | Compound Wikidata genres get their parents (`comedy-horror` is comedy and horror), known kinds (`slasher` is horror) are linked, words that are not the genre (`live-action`) are ignored. A small catalogue shows a horror dislike removing slasher, zombie-comedy and comedy-horror films. |
| `test_big_catalogue.py` | On the 10,000-film catalogue: disliking horror, western, comedy or science fiction removes every film of that family from the full candidate list (and the test first confirms such films exist without the dislike); 24 random groups match the reference exactly; 8-member groups rank within a 1 s budget (they took 1.6-1.8 s before). |
| `test_db.py`, `test_benchmark.py` | SQLite settings behind the faster API, the garbage-collection freeze, and the benchmark's own output. |

The checks were tested against deliberately broken code (each change applied to the original recommender, then reverted): ignoring dislikes failed 6 tests, dropping the "every member must match" rule failed 13, giving people weight 1 failed 4, dropping subgenres from dislikes failed 4, and listing every like in the explanation failed 1. None of the broken versions passed.

### What was wrong

1. **Dislikes were ignored for subgenres on the imported catalogue.** The genre tree had five hand-written entries, so imported genres such as `slasher`, `zombie-comedy` or `spaghetti-western` were not linked to horror, comedy or western. Disliking horror still let 122 films through; comedy 440, crime 210, thriller 188, western 89 (`python -m watchtogether.genre_audit` prints the full table). The same gap meant a comedy like did not reach 440 comedies. Fixed by deriving parents from compound genre names plus a short table of known kinds; the starter catalogue's results are unchanged (0 films differ).
2. **Explanations only listed labels.** A film reached through a liked film said only "Inception", not that it shares the director. Each like now says how it connects; the shortlist card shows it.
3. **Recommendations were slow on the imported catalogue** (1.6-1.8 s for 8 people, up to 2.7 s per request). See `PERFORMANCE_REPORT.md`.

Example shortlists are in `EXAMPLES.md` (generated by `python -m watchtogether.examples --write`).
